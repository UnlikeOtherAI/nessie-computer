# Original session authority

Computer access and an owner namespace do not establish ownership of retained
sessions. Bound content and control need an accepted managed-start association.
Native/external continuity remains unavailable until its own required producer
can prove the original human and history lineage. Inventory is observation only.

The strict protocol transports `ExecutorManagedSessionEvidence`:
`kind: managed_start`, executor ID, original owner generation, owner key, session
ID, actual start command ID and a digest of that structural tuple. The digest
is not a MAC, token or independently spendable authority. Private canonical
admission and fresh original human/custody checks remain necessary.

`ExecutorCodingSessionAuthority` binds one command and operation, executor,
generation, namespace, read/control purpose, at most 32 duplicate-free admitted
identities and a lifetime of at most 30 seconds. Start has no prior targets;
other targeted operations have exactly one. A list's continuation is selection
data and requires fresh preparation on its next use.

The daemon receives `ExecutorSessionPairingSource` only through authenticated
machine claim. It names a real accepted enrollment or code-pairing reference,
executor and machine-key digest; bound sources also pin the original generation.
The actual claim consumer stores that reference beside the bridge config.
Missing, malformed or mismatched source evidence cannot select the explicit
unbound compatibility branch. Mode and generation strings supplied by a caller
do not establish a source. Personal/native principal checks remain independent.

New managed metadata records its actual start command/executor/generation once.
The persistent start journal survives ordinary command-record pruning. A retry
needs that exact original journal and metadata before returning an outcome;
missing, raced or conflicting evidence reports an uncertain outcome without
starting again or retrofitting metadata. Bound lists read only selected managed
identities and never consult the native directory. Bound status reads do not
restart a host. System inventory and withdrawal do not authorize content.

This is an implementation checkpoint. Private stamping/delivery, result and
sidecar publication, viewer leases, full recovery and actual public/private
regressions still need completion and qualification. The cutover requires a
coordinated drain of old API/worker/executor holders; no deployment is authorized.
No native/provider acceptance or complete retained-history claim follows from
these source checks.
