# Original session execute and publication authority

This source checkpoint is not qualified for release or catalog parity.

The original-adapter byte continuation is documented in
[protected provider bytes](protected-provider-bytes.md). Its generic SDK stdin
remains closed pending authenticated serializer correlation. Automatic byte
replies use observed outstanding request IDs and a fixed unsupported response;
the older structural reply grammar below is not sufficient for arbitrary SDK
input authorization.

Bound coding calls use the signed `session_authority` route before execution
and before result publication. The server consumes the captured human origin,
original custody and original selected admissions under current connection and
authorization fences. A response renews only validated authority dates; command
arguments, owner, generation, selection, filter and cursor remain in the digest.
The client limits consumption to five seconds and rejects changed selections.

Viewer demand captures the actual requester's reference and exact admitted
session. It remains read-only even when a new same-human login can view history
after the original credential expires. Actions require accepted execution
custody. Missing requester, admission or authority refuses collection and output.

Results are checked before image sinks and result journals. Bound session
commands publish one scoped text document; raw failures and sidecars are refused.
A managed start records its immutable outcome only after request writing and
host creation return. An absent outcome remains uncertain; replay does not
synthesize success or restart a host.
An existing request or an unconfirmed host spawn also leaves the outcome
uncertain; neither can produce a successful creation receipt.

The render-free `test:executor-private-assignments` gate uses the ordinary Node
test runner through Turbo. Its schema/evidence tests require no Windows ACL
helper and do not prove installed host execution. Native verification remains
separate and is not authorized by this source-only gate.

Nessie must expose exactly T3's sessions and ordering on each individual
machine. The current managed-only admission selection does not meet that goal.
Legacy/native admission and original catalog ordering remain unresolved with
their owning importer and parity work; omission is not a complete catalog.
## Effect-boundary correction checkpoint (8 November 2026)

Bound writes now carry the original exact operation through retained request
intents, secret delivery, host launch and deferred driver turns. Each owner
consumes through the signed session-authority route after its awaited reads.
Expired carriers cannot be revived locally. The host does not concatenate a
previous unconfirmed prompt into a different bound command. Codex queues each
message with its own carrier; expiry refuses that message.

Start reconciliation precedes new-launch root, configuration and quota checks.
The journal, metadata, creation phase and returned evidence must agree. Empty
exclusive claims, missing outcomes and conflicting results remain uncertain.
No replay creates a host. Bound answer claims are retained after partial writes.

This checkpoint is **not ready for runtime integration**. The Windows native
`job-run` / `terminal-run` interface has no signed consumption handshake at its
queued CreateProcessW/ConPTY boundary. The agent guard also relays raw stdin
without per-operation authority. Bound launches through these transports now
refuse before starting a provider; they must not silently use the unguarded
transport. The next implementation must frame each original operation across
the relay, consume at the receiving owner, acknowledge refusal without deleting
intent, and preserve the existing Job Object/personal custody fences. It must
not pass machine credentials to a provider or extend deadlines locally.

Only builtin syntax parsing and whitespace checks ran for this checkpoint.
Handler tests in the private control-plane repository use real enrollment,
signed command acceptance and the owning HTTP route. They are authored but
unrun. Crash-phase replay fixtures are explicit durable-record fixtures, not
proof that an installed host was created. Native, driver, database and installed
qualification remain required; no public pin advancement is recommended.

## Receiver-owned effect transport

The later transport checkpoint replaces the temporary bound-launch refusal.
`job-run-authorized` and `terminal-run-authorized` use an explicit inherited
control pipe, separate from provider stdio. The native receiver clears handle
inheritance before provider creation. The agent guard uses a separate inherited
pipe beside its existing identity/lifetime IPC channel. Providers receive no
machine key, refresh material, authority reference or control endpoint.

Each ordered offer binds the original session authority and exact local payload
bytes. The receiver hashes that wire image, issues a fresh nonce, and asks the
original host to consume the owning signed HTTP route. The host answers only
for its pending sequence, digest, nonce and original executor/owner/generation,
connection epoch, authorization revision and selected original start. Replays
or substitutions refuse. No independent local identity issuer is introduced.

A receiver consumes immediately before launch, again before resuming a suspended
Windows process, and before each input write. It acknowledges accepted only
after the actual effect call; partial writes and lost acknowledgement remain
uncertain. Disconnect closes the channel and ends the contained process rather
than granting an unguarded retry. Native/guard provider responses have a separate
structural response-only grammar; they cannot carry new provider requests or
human input. Terminal device reports have a bounded control-sequence grammar.
Neither kind grants control authority or renews its original carrier.

Freshness is bounded, not instantaneous remote revocation: an owning-route
consumption grants at most five seconds. The receiver checks the deadline and
round-trip elapsed time immediately before the OS/API call, and reconsumes after
intervening waits. Scheduling inside a kernel or provider after that call is not
a second authority boundary. A carrier that expires while waiting is refused;
only the actual signed route can refresh a still-live carrier.

Host `effect-intents` persist before dispatch. A crash before or after provider
acceptance never authorizes dispatching that request again. The separate outcome
says `accepted_by_driver`; a queued Codex message is not mislabeled as provider
completion. Each deferred turn keeps its own original authority and message.
Terminal helper acknowledgements cover the inner ConPTY receiver, not merely
acceptance by the outer process relay. Start replay remains read-only and precedes
new-launch-only policy/root/quota checks.

The registered custody gate includes receiver nonce/digest/deadline/replay tests.
The private effects gate adds the actual signed issuer, native launch crash
phases, revoked native input and a provider-active deferred Codex regression.
These are synthetic development fixtures. Qualification results and exact
revision/helper hashes are recorded separately; none establishes signed installed
personal custody by itself.

The broker and host share the same in-memory original carrier: a successful
signed consumption updates that carrier, rather than leaving a stale private
copy in the caller. Native relay threads own duplicated Job handles so a late
channel failure cannot act on a closed/reused handle.

Receiver elapsed-time checks use a monotonic clock as well as the permit's wall
deadline. Clock rollback cannot lengthen a pending challenge. Authorized Job
launch refusals retain the wrapper's exit code 125.

## Protected Windows continuation

The terminal driver now starts its fixed `terminal-session-process` through
`executorChildCommand`, just like other compiled executor children. The managed
native creator registers that Node generation before it runs. An outer Job
alone cannot satisfy the inner ConPTY helper's direct-parent `HostAcquire`
check. Development Node still cannot establish release custody.

When an authorized Job's program exits, the helper explicitly terminates the
existing Job before requesting service clearance. Its input relay retains a
duplicate Job handle, so closing only the main handle would leave descendants
alive until the helper itself exited. Termination failure remains a refusal;
only the service's independent membership observation can release the host lease.
The added kernel regression retains the duplicate through its child-exit check.

These are source corrections, not a signed installed launch result. Qualification
needs one exact protected candidate: compiled publisher EKU, final signed helper,
manifest-pinned Node and bundle, a compatible authenticated service, and an actual
managed parent generation from that candidate. The supported creator runs only
its fixed CLI bundle. It cannot start a TypeScript test loader or an arbitrary
test entry instead. Signed-route fixtures invoked by development Node remain
separate from a synthetic installed journey through the normal coding bridge.
No helper override, fixture-only managed entry or relaxed service admission is
introduced. Personal providers and existing conversations are not test inputs.

## Provider input acknowledgement and stop debt

`AgentProcess.writeProtocol(text)` returns `Promise<void>`. The same ordered
input lane carries ordinary input, structural automatic replies and end-input.
It awaits the native receiver outcome, or the writable callback for an
unpackaged pipe. That acknowledges transport delivery, not provider completion.
Exit, pipe failure, timeout or rejected authority fails the lane permanently;
a late callback cannot revive it. Do not replay uncertain input. Automatic
replies cannot carry provider methods or grant a human operation. Codex result
and error responses await this promise. Request withdrawal also awaits its
reply and records `delivery_unknown` when acknowledgement fails.

Every `AgentProcess` exposes `confirmHostExecutionStopped(snapshot?, effect?)`.
`exited` resolves `{ code, clearance: 'stopped' | 'unknown' }`; an exit code is
never clearance. A positive `stopTree` result is required even without personal
credentials. Unknown clearance retains the identity, prevents completed close
and replacement, and can be reconciled by another clearance attempt. Startup
failure throws `AgentProcessStopUnproved` with the identity when known, or the
spawned PID when identification failed. The PID is debt evidence, never a
replacement birth identity. Missing proof capability refuses before spawn.
Host recovery and supersession obey the same rule. POSIX group/table sweeps
still report unknown; they do not become kernel containment proof.

The Windows process exchange keeps the deadline check and its kill branch in
one PowerShell `if`/`else` statement. A statement separator before `else` caused
the catch block to swallow a command error and report completion without a
kill. An expired per-target deadline still refuses termination. The focused
Windows source gate exercises current and expired deadlines, interrupted warm
cleanup followed by cold cleanup, identity replacement and actual Job children.
This process exchange is not positive protected Job clearance by itself.

On 9 November 2026, Maxis/Windows 11 and Node 24.19.0, the six public build
tasks passed (four cached). The focused Windows source run passed all five

The direct outside-runner probe reproduced a surviving child and a false

No native source changed or was rebuilt. Full Windows session-start acceptance

The original T3 adapters must use these low-level contracts directly. This is
not permission to replace original `makeCodexAdapterV2` or the Claude runner
with Nessie's managed driver queue. T3 finite-effect authority needs the
broker/authentication producers' verified in-process grant, including exact
executor, environment, thread, provider session, epoch, runtime generation,
request digest and explicit native association. Managed `session_start`
authority cannot stand in for that grant.

The focused `test:executor-private-assignments` gate includes
`agent-process-input.test.ts` and receiver refusal/late-permit cases;
`test:personal-inference` includes leased and unleased stop-debt cases;
`test:live-sessions` covers the changed async withdrawal consumers. These new
cases are authored, not run in the source-only continuation. Protected signed
launch, revocation and crash journeys remain separately required.

## Original T3 finite effects

`requestT3EffectAuthority(directory, grant, signal?)` in
`src/coding-session/session-effect-authority.ts` accepts only the broker's
`VerifiedT3EffectGrant`. Its private issuance token and WeakSet are checked;
JSON, a matching method shape, and caller-supplied callbacks cannot mint one.
The carrier reconsumes through `createT3EffectAuthorityClient` and the dedicated
`POST /api/executor-daemon/t3/effect-authority` route. The enrolled state is
loaded from the protected directory before and after that exchange. The grant's
`issuerOrigin` must equal that enrolled HTTPS origin, and executor ID, epoch,
machine key and API URL must remain unchanged. Aborted, expired, changed or
revoked authority refuses before the effect. This does not reuse the native
`session_authority` endpoint.

The strict `T3EffectGrantReference` retains executor, environment, original
thread, original provider session, connection epoch, runtime generation,
correlation and command IDs, the signed backend offer's HMAC request digest,
and the explicit native association. Native driver, native ID, continuation-home
key and history-home key remain separate fields. A new operation may target
the same process, but must carry its own verified grant; renewal cannot change
the original operation. The original request/digest binds its provider-instance
selection; the native session ID never substitutes for any original T3 ID.

`session-effect-scope.ts` owns that equality contract. `EffectBroker`,
`EffectReceiver` and native `session_effect_scope.rs` reject cross-kind,
cross-target and cross-association frames. The wire digest also binds issuer
origin, including automatic reply frames. The native receiver's private managed
host performs the protected-enrollment comparison and actual signed consumption
for each fresh challenge. No signing key, authority endpoint or credential is
passed to the provider.

Inherited references retain the directory and issuer origin. Parsing such a
reference is only preparation: the same signed route must recreate verified
authority before any effect. `requestT3EffectAuthority` does not accept that raw
reference as an in-process grant. Managed request inboxes and their effect
intent writer reject T3 carriers; original T3 request receipts remain owned by
the original admitted lane. Streams never become finite provider input grants.

The broker/authentication workers own the issuer and per-target admission.
Their prerequisite exports are composed by the parent; this source continuation
does not import their commits or claim a successful bound route. Tests in
`test/t3-session-effect.test.ts` cover forged grants, exact target separation,
issuer substitution, expiry and refusal followed by a late permit. Native
target-matching fixtures are in `session_effect_scope.rs`. They remain authored
and unrun until the serial qualification window.

There is no authoritative mapping from the provisional
`ProviderCredentialReferences.resolve(namespace, bindingId)` seam to a native
association. The pinned source uses its host credential seam for Cursor;
Codex ChatGPT token storage is T3-owned and excluded. Neither original native
Codex nor Claude transport calls that seam. It stays unbound: do not fabricate
a grouping key, equate a provider-instance ID to a native ID, or persist a
second credential/identity authority.

Source bridge fixtures persist an explicit synthetic unbound-local pairing
reference through the production local claim store and carry that exact reference
in reserved metadata. Missing-source and fabricated-mode negatives remain denied;
these fixtures establish no bound UOA authority or installed readiness.

Request responders may finish synchronously or return an acknowledgment promise.
The request book normalizes either result before publishing delivery and awaits
asynchronous acknowledgments, including their failures.

Unbound local daemon viewer actions retain the enrolled pairing reference and
forward the selected owner and action idempotency key. Bound actions keep their
original sealed operation metadata. A changed reviewed configuration refuses a
new start before resolving any configured root.

Intentional provider stops remain attached to the exact process until its exit
callback drains. Positive tree clearance is still required; a delayed callback
cannot replace the recorded limit/close reason or interrupt a newer process.
Private state replacement reuses the bounded atomic rename primitive, retaining
the secured temporary inode while a Windows reader briefly holds the old file.
